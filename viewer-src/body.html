Code Explorer

Local model

Explores the selected project's graph and source, then answers questions with file and line references.

Useful for
Understanding architecture, following code paths, finding integrations, and investigating API routes and their request and response types.
How it works
Searches graph evidence, reads relevant source excerpts and asks a local Ollama model to explain them. It checks that citations refer to source it read.
Needs
A project graph and an installed Ollama model. The viewer also needs the local Token Graph server.
Access
Read-only: it does not edit files or build the graph.
Limits
Graph links are hints, and citations do not guarantee a claim is correct. Routes can be missed; verify important answers in the source.
Try asking
  • How is this project structured?
  • Where is authentication enforced?
  • Which endpoints are defined, and what do they accept and return?
Run in a terminal
python3 /path/to/token-graph/scripts/explore_agent.py /path/to/project 'How does authentication work?'

Log Analyzer

Terminal

Groups errors and repeated events, summarizes their frequency and timing, and can ask a local model to explain the evidence.

Useful for
Investigating failures, repeated errors, affected services and related traces.
Sources
Local log files and saved Argo CD or Loki responses. A separate terminal tool can retrieve logs through configured Grafana or Argo CD MCP servers.
Output
Counts, grouped errors, timestamps and trace groups; optional model findings distinguish observations from hypotheses.
Needs
A log file or configured log source. Ollama is needed for model interpretation; --no-llm runs the local analysis alone.
Limits
Results cover the supplied sample, and timing does not prove cause. Redaction is best effort; review results before sharing.
Try asking
  • What errors happened most often?
  • When did failures begin, and which services were affected?
  • What should I investigate next?
Run in a terminal
python3 /path/to/token-graph/scripts/log_analyzer.py /path/to/application.log 'What failures occurred?'

Add --no-llm for statistics without a model. Use --source argocd or --source loki for saved responses.

Repo Scout

Terminal

Investigates a focused question about a repository and returns a structured report with source references.

Useful for
Tracing behavior and callers, finding related tests and rules, and identifying what remains uncertain.
Output
Repository and question, behavior, callers, tests, rules, uncertainty and graph queries.
Needs
A repository and its project graph. An installed local Ollama model adds behavior explanations; --no-llm reports code-found fields without one.
Git refs
Use --ref to inspect a committed revision. The scout builds and caches a separate snapshot and graph.
Limits
Source references and model checks help review an answer; they do not prove every claim. Verify important findings in the source.
Try asking
  • How is a player token issued?
  • Who calls the payment handler?
  • Which tests cover this endpoint?
Run in a terminal
python3 /path/to/token-graph/scripts/local_scout.py /path/to/project 'How does authentication work?'

Add --ref origin/main to inspect a committed revision, or --no-llm to skip model interpretation.
